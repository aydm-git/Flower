Чечектер — Цветочный магазин на Flask

Веб-приложение для выбора букетов и оформления заявок на доставку или самовывоз.
Проект создан в учебных целях для командной разработки с Python, Flask и Git.

## О проекте

Покупатель открывает каталог и страницы букетов, добавляет товары в корзину и отправляет заявку.
Корзина хранится в браузере. Сервер проверяет данные, рассчитывает сумму по ценам из базы
и списывает остатки в одной транзакции с сохранением заказа. Онлайн-оплата не реализована.

Функционал:

- Каталог с фотографиями, описанием, составом и доступным количеством.
- Доставка или самовывоз, дата и время, открытка и комментарий.
- Админка: товары, остатки, фотографии, поиск заказов и изменение статусов.
- Возврат товара при отмене и повторное списание при восстановлении заказа.
- Уведомления о новых заказах в Telegram, если интеграция настроена.
- Выручка в админке учитывает только заказы со статусом «Доставлен».

## Технологии

Python 3.11+, Flask, Flask-SQLAlchemy и SQLite, Flask-WTF (защита форм CSRF),
Jinja2, HTML/CSS и JavaScript. `tzdata` обеспечивает работу часовых поясов в том числе на Windows.

## Локальный запуск

Команды для PowerShell из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Если `.env` уже существует, сохраните его настройки вместо повторного копирования.
Заполните файл по инструкции ниже, затем запустите приложение:

```powershell
.\.venv\Scripts\python.exe backend/app.py
```

Сайт доступен по адресу `http://127.0.0.1:5000`, вход администратора — `/login`, админка — `/admin`.
При первом запуске создаются база `instance/flower.db`, каталог `static/uploads/` и четыре демонстрационных товара.
На Linux/macOS используйте `.venv/bin/python` вместо `.\.venv\Scripts\python.exe`.
Встроенный сервер предназначен для локальной разработки; для размещения используйте WSGI-сервер и HTTPS.

## Настройка .env

Приложение читает `.env` из корня проекта. Переменные окружения процесса имеют приоритет.
Файл `.env`, база и загруженные фотографии исключены из Git; не добавляйте секреты в коммиты.

| Переменная | Назначение |
| --- | --- |
| `SECRET_KEY` | Обязательный случайный секрет для подписи сессий и CSRF. Без него приложение не запускается. |
| `ADMIN_USERNAME` | Логин единственного администратора. |
| `ADMIN_PASSWORD_HASH` | Хеш пароля Werkzeug. Обычный пароль сюда не записывается. |
| `SHOP_TIMEZONE` | Часовой пояс IANA; по умолчанию `Asia/Novosibirsk`. |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота; необязательный. |
| `TELEGRAM_CHAT_ID` | ID одного или нескольких чатов через запятую. |
| `TELEGRAM_PROXY` | Необязательный адрес HTTP/SOCKS-прокси. |
| `FLASK_DEBUG` | `1` включает отладку при запуске `backend/app.py`; для обычного запуска оставьте `0`. |

Сгенерируйте секретный ключ:

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_hex(32))"
```

Команда выводит 64 шестнадцатеричных символа. Скопируйте результат в `SECRET_KEY`.
Для хеша пароля выполните:

```powershell
.\.venv\Scripts\python.exe -c "from getpass import getpass; from werkzeug.security import generate_password_hash; print(generate_password_hash(getpass('Admin password: ')))"
```

Введите пароль в скрытом приглашении и скопируйте полученный хеш в `ADMIN_PASSWORD_HASH`.
Пример структуры настроек, где значения в угловых скобках нужно заменить:

```dotenv
SECRET_KEY=<случайный ключ>
ADMIN_USERNAME=admin
ADMIN_PASSWORD_HASH='<полный хеш Werkzeug>'
SHOP_TIMEZONE=Asia/Novosibirsk
```

Если логин или хеш не заданы, каталог работает, но вход администратора недоступен.
После изменения `.env` перезапустите приложение. В HTTPS-развёртывании также включите
`SESSION_COOKIE_SECURE=True` в конфигурации Flask.

## Telegram

Укажите токен своего бота и ID чатов, в которые бот имеет право отправлять сообщения:

```dotenv
TELEGRAM_BOT_TOKEN=<токен бота>
TELEGRAM_CHAT_ID=<ID первого чата>,<ID второго чата>
TELEGRAM_PROXY=
```

При необходимости задайте прокси, например `socks5h://127.0.0.1:1080`.
Зависимость `requests[socks]` уже включена в `requirements.txt`.

После сохранения заказа сервер отправляет номер заказа, контакты, состав, сумму,
способ получения, дату, время и комментарии. Проверить интеграцию можно тестовой заявкой:
она должна появиться в админке и в указанных чатах. Заявка списывает реальные остатки этой базы;
после проверки отмените её в админке.

Если токен или список чатов пуст, уведомления отключены. Ошибка Telegram записывается в журнал,
но сохранённый заказ остаётся в базе. Отправка выполняется в фоновом потоке без очереди и повторных
попыток: при остановке процесса уведомление может потеряться. Проверяйте заказы в админке.

## Доставка и часовой пояс

Даты, время создания заказа, серверная проверка и счётчик «к выдаче сегодня» используют `SHOP_TIMEZONE`.
Форма показывает время в этом же поясе, независимо от часового пояса и настройки часов покупателя.

- Доступны даты от сегодняшней до 60 дней вперёд включительно.
- Для сегодняшнего интервала до его окончания должно оставаться **больше часа**.
  Например, в 11:00 интервал 10:00–12:00 уже недоступен.
- «Как можно скорее» доступно только сегодня с 10:00 до 20:00 включительно,
  чтобы двухчасовая доставка укладывалась в окно 10:00–22:00.
- Эти правила применяются также к самовывозу. Сервер повторно проверяет их при отправке формы.

## Обновление базы и отмена заказов

Перед первым запуском новой версии остановите приложение и сохраните резервную копию
`instance/flower.db` и каталога `static/uploads/`. Сначала запустите один процесс для обновления схемы,
затем остальные рабочие процессы.

`ensure_schema()` автоматически добавляет в таблицу заказов два поля:

- `items` — JSON со снимком ID, названия, количества и цены каждой позиции.
- `stock_released` — признак возврата остатков, исходно `false`.

Существующие заказы и поле `flower` сохраняются. При отмене нового заказа возврат выполняется по ID;
переименование товара не мешает возврату. Повторная отмена ничего не добавляет.
Восстановление отменённого заказа повторно резервирует товары; если их недостаточно или они скрыты,
заказ остаётся отменённым. Ошибка в одной позиции откатывает всю операцию.
Товар, связанный с заказом, нельзя удалить через админку — его можно скрыть из каталога.

Для старого заказа без `items` приложение разбирает строку `Название (N шт), ...`
при первой операции, меняющей остатки. Каждый товар должен иметь единственное точное совпадение
названия в текущем каталоге. Полученные позиции сохраняются в JSON; историческая цена позиции
остаётся `null`, поскольку её нельзя достоверно восстановить. Общая сумма заказа не меняется.

При неизвестном или неоднозначном названии, повреждённой строке, удалённом товаре либо превышении
лимита склада операция прекращается с сообщением о ручной сверке. Автоматически сопоставить
переименованные товары или отличить новый товар с повторно использованным старым названием невозможно.
Для таких заказов нужно проверить исходные данные и заполнить правильные ID и количества в `items`
на копии базы, затем применить проверенную корректировку к рабочей базе.

В старой версии отмена не возвращала товар. Поэтому ранее отменённые заказы получают
`stock_released=false`: повторное назначение статуса «Отменён» вернёт их остатки ровно один раз.
Если остатки уже возвращались вручную, перед этой операцией необходимо сверить склад и установить
для соответствующего заказа `stock_released=true`, иначе возврат будет повторным.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Ожидаемый результат — `OK`. Тесты используют отдельные временные базы и отключают Telegram.
Проверяются изображения, некорректные корзины, часовой пояс, границы доставки, одновременная покупка
последнего товара, откат транзакций, отмена и восстановление заказа, миграция и расчёт выручки.
